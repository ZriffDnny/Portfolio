# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal portfolio for Zariff Danial, built with Vite 8 and React 19 and deployed to Vercel at https://zariffdanial.vercel.app/. All content lives in the locale files and a few data modules; there is no CMS. The design system is documented in [docs/DESIGN.md](docs/DESIGN.md).

## Commands

- `npm install`: install dependencies (`.npmrc` sets `legacy-peer-deps`; the eslint-plugin-react and eslint-plugin-jsx-a11y peer ranges stop at ESLint 9 although both run fine on 10)
- `npm run dev`: Vite dev server on http://localhost:3000 (strict port, hot reload)
- `npm run build`: production build to `dist/` (target es2020). Vite does not run ESLint, so a green build says nothing about lint.
- `npm run preview`: serves `dist/` on http://localhost:4173 with the same security headers as vercel.json and mirrors its hosting rules through the `previewLikeVercel` plugin in vite.config.mjs: a route with a trailing slash gets a 308 to the slash-less path, and an unknown path gets `dist/404.html` with status 404; the closest thing to Vercel locally
- `npm run lint`: ESLint over the source tree (tools/, dist/ and build/ are ignored) with the flat config in [eslint.config.mjs](eslint.config.mjs) (@eslint/js, react, react-hooks, jsx-a11y). This is the gate before pushing: it must exit 0 with zero errors and zero warnings. Fix the code rather than disabling rules; there is no inline disable anywhere in `src`.
- `npm test`: vitest, single run (`npm run test:watch` for watch mode). [src/App.test.jsx](src/App.test.jsx) renders the whole app on the home page (chrome, title, canonical, the preloader once per session and never under reduced motion, the theme from storage or the OS, count-ups that jump under reduced motion, the hero phone's tilt switched off under reduced motion, the About jump chips, the analytics opt-out handed to both Vercel components and its toast shown once under StrictMode); [src/routes.test.jsx](src/routes.test.jsx) renders every route in `routes.mjs` plus the 404 under StrictMode and `RootErrorBoundary`, checking one `h1`, the `meta.*` title, the canonical (none and `robots noindex` on the 404), `lang="en"` on a case study under Bahasa Malaysia, no `console.error`, and the scroll position restored on Back; unit tests sit next to their subjects (`utils/utils.test.jsx` for the storage helpers, `reloadOnce`, `lazyPreload`, `formatMonth` and the analytics opt-out, `hooks/usePageMeta.test.jsx`, `components/ErrorBoundary.test.jsx`). jsdom shims live in [src/setupTests.js](src/setupTests.js), which also registers the jest-dom matchers: `matchMedia` answers false until a test calls `window.setMedia(query, matches)` (reset after each test), every `IntersectionObserver` target reports itself in view on a microtask, `fetch` rejects (no test reaches the network), and `scrollTo` and `scrollIntoView` are no-ops. [src/contract.test.js](src/contract.test.js) enforces the written rules with plain file reads: en/ms key parity and matching `{{variables}}`, no em or en dashes in any text file of the repository (the two files that look for them, `src/contract.test.js` and `tools/resume/check.js`, build the characters from char codes so they never match themselves), the route list in `routes.mjs` against vercel.json, the sitemap and the `<Route>` paths in App.jsx, a title and description for every route and project in both locales, Open Graph images that exist at their declared size, the case-study chain in `studies.js` against the article routes and the `caseStudy` and `selectedForHome` entries in `projects.js`, the vercel.json rules (`trailingSlash: false`, no `cleanUrls`, no catch-all rewrite, the `/(.*)` header rule, the asset and resume cache rules, the resume redirects), the two Content-Security-Policy origins against the Formspree endpoint, the installed calendar library and the sweep, the install counts across `data/mytax.js`, both locales, `index.html` and the resume, the home shell's tags against `meta.home` and `meta.homeDesc`, no `!important`, no CSS framework, no freelance, overseas or relocation words in the copy, the contact form's `_gotcha` and the "Portfolio: " prefix on its `subject` field (never the undocumented `_subject`), and same-page jump links that go through `<Link to="#id">` (the skip link is the only native `href="#"`, and it moves focus itself in its onClick). The vitest block lives in [vite.config.mjs](vite.config.mjs).
- `npm run qa` - the browser quality sweep, [tools/qa/sweep.mjs](tools/qa/sweep.mjs). Run `npm run build` first: the script starts `vite preview` on 4173, opens every route in `routes.mjs` plus a 404 in headless Chromium in both themes at 1440 and 390, plus Bahasa Malaysia passes on desktop dark and mobile dark, scrolls each page so the reveals fire, and fails on any console or page error (a CSP violation included), horizontal overflow, a page without exactly one `h1`, a serious or critical axe violation (WCAG 2.0 A and AA, 2.1 AA), a web font that did not load, a document title that is not the route's `meta.*` title in that language, an `html lang` that is not the pass's language, a canonical that is not the route's own URL or a `robots noindex` on an indexable page, a 404 without `robots noindex` or with a canonical, an English-only case study whose `.cs-page` is not `lang="en"`, a document that did not answer 200 (the 404 route must answer 404 under `--serve`; against another server that is only noted), a resume viewer that showed its error placeholder or drew no page within 30 s, or a contribution calendar that did not draw its data (when its API failed on its own the calendar must show its error text instead; a request to that API still unanswered after 20 s is a note, not a failure). Full-page screenshots, the axe JSON per page and `report.json` land in `tools/qa/output/` (gitignored). Set `PW_CHANNEL=chrome` locally to use the installed Chrome instead of downloading Playwright's Chromium (otherwise `npx playwright install chromium` once). Without `--serve` the script sweeps a server that is already running (`--url=http://localhost:3000` for the dev server); `--routes=home,about` limits it to a subset. When the target is not https it answers Vercel's analytics scripts with an empty script (the preview server has none), so a `--url=https://...` run loads the real ones under the page's CSP; it reports, without failing, an HTTP or network failure of the third-party contribution calendar API; every other failed load fails the page.

Vercel runs `npm run build` on a Node release that satisfies `engines` (a floor of 22.22.2; `.nvmrc` and CI use 22) and serves `dist/`. [vercel.json](vercel.json) pins the Vite preset and output directory, sets `trailingSlash: false` (so `/about/` gets a 308 to `/about`), redirects `/resume.pdf` and any old fingerprinted `/assets/Zariff-Danial-Resume-*.pdf` to `/Zariff-Danial-Resume.pdf`, has one rewrite per client route and no catch-all, sends security headers on every page and file response (nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options DENY; a redirect carries only HSTS, which Vercel adds itself), marks `/assets/*` immutable and keeps `/Zariff-Danial-Resume.pdf` at `max-age=0, must-revalidate` so the stable URL always serves the current file. Unknown paths fall through to `dist/404.html` with status 404, and the app renders NotFound there. Do not add a catch-all rewrite or switch on `cleanUrls`: unknown paths must keep returning 404.

Every client route lives in [routes.mjs](routes.mjs) (name, path, `meta.*` keys, og:type, English-only flag and optional Open Graph image). A small `route-html` plugin in [vite.config.mjs](vite.config.mjs) reads it and writes a static shell per route: `dist/<path>.html` for every page and `dist/index.html` for home, each a copy of `index.html` with that route's title, description, canonical and Open Graph and Twitter tags taken from `meta.*` in `en.json` (og:type `article` on the case studies; og and twitter image tags for routes that name one), plus `dist/404.html` (meta.notFound, `robots noindex`, no canonical or og:url). The rewrite for each route serves its shell at `/<path>` (vite preview does the same by itself), so crawlers and link previews see the right page without running JavaScript. The plugin also writes a Content-Security-Policy `<meta>` into every shell, ahead of the inline theme script, with that script's sha256 recomputed on each build; a new third-party origin (fetch, script, image, font) must be added to `contentSecurityPolicy()` in vite.config.mjs or production blocks it and the sweep fails (the contract test checks the two origins it allows against the code that uses them). The build fails if a tag it swaps is missing from `index.html`, if an English description is over 160 characters, if the JSON-LD does not parse, or if the page has any other inline script. Adding a page means an entry in routes.mjs, a rewrite in vercel.json, a sitemap entry, a `<Route>` in App.jsx and `meta.<key>` plus `meta.<key>Desc` in both locale files; the contract test names whichever is missing. `src/main.jsx` turns the browser's scroll restoration off (ScrollToTop restores positions itself), applies an `?analytics=off` or `?analytics=on` in the address (see `utils/analytics` below) and takes it out of the address before the router reads it, and wraps the app in `RootErrorBoundary`. A route chunk that fails to load (usually a tab still open across a redeploy, whose chunk names have gone stale) reloads the page only when a render needs it, only for a chunk that failed to fetch (a module that throws while it evaluates goes straight to the route's error boundary), never from a background warm-up, never offline and at most once per 10 s ([utils/reload.js](src/utils/reload.js), called from `lazyPreload`); otherwise the route's error boundary shows a Reload button.

CI: [.github/workflows/quality.yml](.github/workflows/quality.yml) runs on every push to `main` and every pull request, on Node 22: `npm ci`, `npm run lint`, `npm test`, `node tools/resume/check.js` (the committed PDF still parses), `npm run build`, then `npm run qa` in Playwright's own Chromium, which is cached between runs by playwright version. The actions are pinned to commit SHAs (Dependabot bumps them), and a pull request run cancels the one it supersedes while a push to `main` always runs to completion. Any red step fails the job, and `tools/qa/output` is always uploaded as the `qa-screenshots` artifact (kept 14 days) so a failure can be inspected from the screenshots and axe reports. This is the same standard the site was reviewed against; a change that breaks it in either theme, either viewport or in Bahasa Malaysia should not land. [.github/workflows/weekly.yml](.github/workflows/weekly.yml) runs on Mondays and by hand: [tools/qa/links.mjs](tools/qa/links.mjs) checks every external link in `src/`, `index.html` and the resume (it never requests the Formspree form), and [tools/qa/production.mjs](tools/qa/production.mjs) checks the live site's titles, canonicals, every redirect in vercel.json, the 404 status, the headers, the CSP and that the Vercel analytics and Speed Insights scripts answer; a request is retried once before it counts as failed. [.github/dependabot.yml](.github/dependabot.yml) opens monthly update PRs (npm minor and patch grouped, majors separate, and GitHub Actions).

## Architecture

Single-page React 19 app with `react-router-dom` v7 (declarative API: BrowserRouter, Routes, Route, Link, NavLink). Every file that contains JSX has a `.jsx` extension; hooks, data, utils, i18n and CSS keep their names, and imports omit extensions. Entry: [index.html](index.html) at the repo root (the inline theme script, the preloads for the three latin font files, meta tags, JSON-LD as an `@graph` of WebSite and Person, and a static `<noscript>` paragraph with contact links; files in `public/` are referenced as `/name`) → [src/main.jsx](src/main.jsx) (`createRoot` + `StrictMode`) → [src/App.jsx](src/App.jsx), which loads each route through `utils/lazyPreload` inside `<main id="main">` and a `RouteErrorBoundary`, mounts the shared chrome, and shows the wordmark preloader only on the first visit of a browser session, never under reduced motion (a 0.15 s hold and a 0.15 s fade, run as a CSS animation so a busy main thread cannot stretch it). Route chunks are warmed while the browser is idle, once the window `load` event has fired, except `/resume` (warmed when a pointer reaches a Resume link or keyboard focus rests on one for 300 ms) and the 404, and not at all under Data Saver or on a 2G connection. StrictMode double-invokes effects in dev, so every effect (count-ups, observers, timers) must be idempotent.

Routes:

The pdf.js worker is the one bundled with the installed `pdfjs-dist`, resolved with `new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`, so there is no CDN dependency and the versions can never drift

Data modules in [src/data/](src/data/): `projects.js` (the project list; copy keys are `projects.<id>_title` and `projects.<id>_desc`), `mytax.js` (store links, press, the MyTax screenshot list), `screenshots.js` (every phone screenshot with its 300px rendition and intrinsic size; `register(full, small)`, `srcSetFor()` and `dimensionsFor()`), `stats.js` (years coding is computed from May 2019). Hooks in [src/hooks/](src/hooks/): `useCountUp` (jumps straight to the value under reduced motion), `useInViewOnce`, `usePageMeta` (title, description, og and twitter title and description, canonical and og:url from the lowercased path without a trailing slash, optional `noindex`, which removes canonical and og:url). Utilities in [src/utils/](src/utils/): `formatMonth(iso, lang)` renders `YYYY-MM` dates in the active language, `lazyPreload` (lazy routes that render synchronously once loaded), `reload` (`reloadOnce` for a missing chunk), `motion` (`prefersReducedMotion`, `scrollBehavior`), `storage` (`readStorage` / `writeStorage` / `removeStorage`, which never throw when a browser blocks site data), `analytics` (keeps the owner's own browsers out of Vercel Web Analytics and Speed Insights: opening any page with `?analytics=off` stores the `va-disable` flag from Vercel's opt-out docs in that browser's localStorage, `?analytics=on` removes it, and App confirms either with a toast; `dropIfOptedOut` is the `beforeSend` of both components and drops every page view and vital while the flag is there. The flag belongs to one browser profile on one origin, so private windows forget it, in-app browsers (a link opened inside LinkedIn) and Vercel's per-deployment URLs never see it, and on Apple devices (Safari and every iPhone browser) WebKit deletes it after 7 days of browser use without a click or tap on the site; a bookmark typed as `https://zariffdanial.vercel.app/?analytics=off` sets it again on every visit, before either script sends anything) and `printReveal` (shows unrevealed blocks while printing).

Contexts: `ThemeContext` (the stored choice, else the OS colour scheme, dark unless it asks for light; persisted in localStorage `theme` through the guarded storage helpers, and applied before first paint by an inline script in [index.html](index.html) that follows the same order) and `ToastContext`.

i18n: `react-i18next` with [en.json](src/i18n/locales/en.json) and [ms.json](src/i18n/locales/ms.json). The two files must keep key parity, and every visible string goes through `t()` (the one exception is `RootErrorBoundary`, which must not depend on i18n).

## Styling

No Bootstrap and no `!important` anywhere. Components read design tokens only.
- [tokens.css](src/styles/tokens.css): every colour, type, spacing, radius, shadow, motion and z-index token; dark values on `:root`, light values under `html[data-theme="light"]`
- [base.css](src/styles/base.css): reset, typography, focus rings, `scroll-padding-top` for the fixed nav, scrollbar, reduced motion, the large-text breakpoint (`max-width: 20em`, which follows the reader's default font size), the print stylesheet, and the shared classes (`.container`, `.section`, `.eyebrow`, `.section-head`, `.btn`, `.chip`, `.surface`, `.prose`, `.meta-list`, `.phone`, `.wordmark`, `.site-backdrop`)
- [chrome.css](src/styles/chrome.css): navbar, mobile menu, footer and the fixed elements, including their forced-colors rules
- One stylesheet per route (`home.css`, `about.css`, `about-sections.css`, `projects.css`, `resume.css`, `uses.css`, `casestudy.css`, `notfound.css`) plus `project-card.css`, `store-links.css`, `stat-tile.css` and `cta-band.css`, each imported by the component that uses it so it code-splits with the route. Home is imported statically in `App.jsx` (it is the landing route); the others are lazy.

`src/index.css` loads fonts, tokens and base; `src/style.css` loads chrome. Fonts (Bricolage Grotesque for display, Inter for body, JetBrains Mono for labels) are self-hosted: variable woff2 files for the latin and latin-ext subsets in [src/Assets/fonts/](src/Assets/fonts/) with their OFL licences, declared in [fonts.css](src/styles/fonts.css) under the same family names, and `index.html` preloads the three latin files. No request leaves the site for fonts.
